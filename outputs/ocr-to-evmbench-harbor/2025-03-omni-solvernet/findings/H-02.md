# [H-02] Underestimated fill gas makes a cross-chain fill acknowledgement fail

## Affected code

- `contracts/solve/src/SolverNetOutbox.sol`: `_fillGasLimit` and `_markFilled`
- `contracts/solve/src/SolverNetInbox.sol`: `_fillHash`

## Root cause

`_fillGasLimit` charges for storage reads and a fixed base amount, but omits
the EVM memory-expansion cost of copying each variable-length `Call.params`
array into memory. An order can therefore encode parameters whose source-side
`_fillHash` execution needs more gas than the gas limit attached to the
acknowledgement `xcall`.

## Prerequisites

- A user can open an order with a sufficiently large `Call.params` payload.
- A solver fills that order on the destination chain and sends the normal
  acknowledgement through `OmniPortal`.

## Exploit sequence

1. The attacker opens an order with oversized call parameters.
2. The solver executes the order on the destination chain and calls
   `_markFilled`.
3. `_markFilled` computes a gas limit using `_fillGasLimit`, which omits
   memory expansion, and sends the `markFilled` message.
4. The source-chain `_fillHash` loads stored calls and expenses into memory;
   its actual cost exceeds the forwarded limit, so `markFilled` fails.
5. The portal consumes the failed message as a failed receipt. The order
   remains pending and its owner later calls `close` to reclaim the deposit.

## Impact

The destination-side execution can transfer the requested assets while the
source deposit remains refundable. An attacker can recover the deposit as well,
creating a concrete loss of deposited protocol assets.

## Code evidence

At the audited commit, `_fillGasLimit` adds only the per-parameter storage-slot
charge and `100_000` base gas. `_fillHash` in `SolverNetInbox` copies
`_orderCalls[orderId]` and `_orderExpenses[orderId]` into memory before hashing.
`_markFilled` supplies the estimate as the `xcall` gas limit.

## Remediation

Include the quadratic and linear memory-expansion terms in the gas estimate,
with checked arithmetic and a conservative buffer. The remediation adds
`divUp` and `mulDivUp` memory-cost terms to `_fillGasLimit`.
