# Silent inactive reward handling permanently consumes validator claims without payment

## Affected code

- `src/token/ValidatorRewarder.sol`: `whenActive`, `notifyValidClaim`

## Root cause

`ValidatorRewarder` implements `whenActive` by returning normally when
`_active` is false. A paused call therefore reports EVM success even though
the guarded function body did not execute. Callers cannot distinguish this
silent no-op from a completed operation.

The loss path is concrete in `ValidatorRewarder`. `notifyValidClaim` is the
system callback that validates a claim and mints or transfers the validator's
share. At the audited commit it is guarded by the silent-return modifier. If
the rewarder is inactive, the callback succeeds without executing any of the
checks or token operations at lines 120-165. The upstream consensus-claim
processor can consequently finalize the claim while the validator receives no
tokens. Because that claim is then treated as consumed, the reward cannot be
claimed again and is permanently lost.

## Preconditions and failure sequence

1. The owner sets the validator rewarder inactive.
2. A valid validator consensus claim reaches the system's claim processor.
3. The processor calls `notifyValidClaim` and expects a revert on failure.
4. `whenActive` returns normally before the reward calculation and token
   mint/transfer code runs.
5. The outer processor observes success and consumes the claim, but the
   validator receives no reward and cannot retry it.

## Asset-loss impact

The validator permanently loses the asset-denominated reward for the processed
claim. The amount depends on checkpoint supply, inflation rate, and blocks
committed, but the loss is not merely delayed availability: the claim is
consumed without payment.

## Remediation

Revert when `_active` is false so the entire outer claim transaction rolls
back and remains retryable. The reviewed remediation in PR #57 replaces the
rewarder's silent `return` with `revert ContractNotActive()`.
